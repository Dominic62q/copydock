# CopyDock v1 scope

**One sentence:** take a Docker Compose app on a laptop, make one bundle, and install it on a Linux server (online or offline) with one script.

Details and background: `CopyDock_Project_Brief.md`. This file is the agreed scope; if they disagree, this file wins.

## In v1

- `copydock package`: reads the Compose file, builds or collects the images, and writes a `.tar.gz` bundle containing:
  - the images
  - a rewritten Compose file with no builds and no pulls (`pull_policy: never`, images pinned by digest)
  - a settings template (no real secrets)
  - a manifest
  - SHA-256 checksums
  - `install.sh`
- One CPU platform per bundle (amd64 or arm64), chosen by the developer and shown clearly.
- `install.sh` inside the bundle:
  - verifies checksums
  - checks Docker, Compose, CPU type, disk space and ports
  - asks for passwords and settings, writes a private `.env` on the server (mode 600)
  - loads the images
  - runs `docker compose up --pull never`
  - reports health per service
- Caddy as an ordinary service in the bundle, plain HTTP on the server's IP or hostname.
- Data survives restarts and reinstalls. Reinstall never deletes volumes.
- Clear, actionable error messages for every failed check.

## Not in v1 (later)

- Multi-CPU bundles
- `copydock deploy user@server` over SSH
- Automatic HTTPS, offline HTTPS / internal CA
- A DNS container
- Upgrades, database migrations, backups, rollbacks
- Package signing
- Registry mode
- Sharing a server with an existing proxy

## Limits

- Destination is Linux with Docker and Compose already installed. The tool checks for them; it does not install them.
- Compose apps using external volumes or networks, `secrets:`, `configs:`, `env_file`, or bind mounts outside the project are rejected with a clear message, not half-supported.
- Build args must be fixed values (no `${VARIABLES}`), and advanced build options (`additional_contexts`, `dockerfile_inline`, build `secrets`/`ssh`) are rejected. Images are built before install, so there is nothing to fill them in from.
- Bind-mounted files that look like secrets (`.env`, `.pem`, `.key`) block packaging unless `--include-secret-files` is passed.
- The destination needs no Python and no CopyDock, only the bundle.

## Stack

Python 3.10+, Typer, Rich, dataclasses + JSON manifest, `docker` / `docker compose` CLI via subprocess, POSIX shell installer, pytest, `pyproject.toml` for PyPI.

## Done when

A sample app (frontend, API, Postgres, Caddy) is packaged on a laptop, copied to a clean Linux VM, and installed with its internet cut off. Then:

- the app loads in a browser
- nothing tried to download anything
- data survives a restart
- no secret appears in the bundle or the logs
- missing Docker, wrong CPU type, low disk and an occupied port each fail preflight with a clear message
